# Kindred Snap — phased build runbook

This is the executable plan. Any session (Fable, Opus 5.5, Sonnet) continues it with `/build-next` (one task per call) or `/loop 12m /build-next` (see `docs/build/LOOP.md`). Phases run in order; inside a phase, tasks run in order. A task is done when its files exist, its tests pass, `npm test && npm run typecheck` are green, the commit is made, and its box is ticked. `docs/build/STATUS.md` records progress and blockers.

Fixed facts every phase relies on: the product rules in `CLAUDE.md`; the design system in `DESIGN.md`; the six caregiver screens in `docs/mocks/M01…M06-*.dc.html`; the staff screens `S00…S05`; the synthetic case in `fixtures/case-synthetic.json` (Dorothy M. Hale, Riverbend Community Hospital, bill $466.00 due 2026-11-30, Medicare max $226.00, discrepancy $240.00 on line 3 Q9967, income $37,560 household 1 = 240% FPL on the 2025 guideline, estimated $169.50 assistance on the corrected $226.00, estimated total $409.50, simulated response after 12 days, new balance $56.50). Money is integer cents everywhere. Dates are ISO strings. All code is TypeScript under `src/`, tests under `tests/` with vitest.

Priority for the 14:30 KST demo: Phases 1 → 2 → 3 → 4 → 5. Phases 6 → 9 complete the acceptance criteria afterwards. If time is short, a phase's "lite" tasks come first; the rest stay unchecked for the next session.

## Conventions for every task

Files named above are the contract between sessions; keep names and exported signatures. Tests mirror `src/lib` one-to-one. Server actions live beside their route in `actions.ts` and call into `src/lib` only; no business rule lives in a component. Copy comes from the mocks; when a mock and this runbook disagree, the mock wins for wording and this runbook wins for behaviour. Commit messages are the ones written here, prefixed by phase.
